# ProofCheck — Architecture & Stack Decisions

**Repo:** `ttb-label-verifier` · **Product:** ProofCheck
**Companion to:** `docs/superpowers/specs/2026-07-21-alcohol-label-verification-design.md`
**Date:** 2026-07-21

This document pins the concrete technology choices. Each row states the decision, the reason it fits
_this_ project's constraints (speed < 5s, dead-simple UX for non-technical users, keyless-by-default,
no PII persisted), and a note on alternatives / how to swap.

## Architecture Rules (Invariants)

These hold across the codebase. They are the "why" behind the module boundaries and the first things
to check in review.

1. **Extraction proposes, matching disposes.** The model / OCR never returns a pass/fail decision —
   it returns only observed values. All verdicts are computed in `lib/matching`.
2. **One shape to rule them all.** Every `VisionProvider` tier returns a Zod-validated `ExtractedLabel`.
   Everything downstream (matching, UI, eval) is tier-agnostic and never branches on which tier ran.
3. **Validate at the boundary.** All model/external output is parsed through a Zod schema before use.
   Invalid cloud JSON → one retry → typed error. No trusting raw model text.
4. **Matching is pure.** `lib/matching` and `lib/ttb` are pure functions with no I/O — fully unit-tested.
5. **The health warning statement is checked deterministically.** Exact against the canonical
   constant after collapsing whitespace runs (a line-wrapped transcription still counts as exact) →
   COMPLIANT; wording/punctuation exact but letter case or spacing differs (prefix still exactly
   `GOVERNMENT WARNING:`) → NEEDS_CORRECTION; anything else → NON_COMPLIANT. Never fuzzy, never
   model-judged.
   (Rationale: spec §6 — TTB approves all-caps warning bodies in practice; 9/10 real COLAs in
   `eval/samples/` do this.)
6. **Keyless by default.** The app must run with zero env vars (mock + local OCR). Cloud tiers are
   strictly opt-in via an API key.
7. **Secrets server-side only.** API keys are read only in server code / API routes and never imported
   into client components.
8. **Persist nothing sensitive.** No database, no disk writes of labels or application data. Processing
   is ephemeral.
9. **Fail per item, not per batch.** One bad label never aborts a batch; errors surface per row.
10. **Naming follows the vocabulary.** Code identifiers use the exact terms in the table below.
11. **The escalation ladder is OFF by default, and blind to application data.** It is opt-in
    (`ESCALATION_ENABLED=1`, or dev mode's "Re-read weak fields" switch, which sends `escalate=1`
    per request) because measurement showed ~72% more cloud latency and ~55% more model calls for a
    null accuracy gain — don't restore it to the default path without new evidence. When enabled:
    repair triggers are extraction-intrinsic
    (absent, or below `CONFIDENCE_NEEDS_CORRECTION_THRESHOLD`) and never a comparison against
    `ApplicationData` — a loop that retried until the label agreed with the application would
    manufacture APPROVEDs. Repairs merge monotonically (a repair may only improve a field), the health
    warning statement is **fill-only** (a repair may fill an absent warning but never replace a
    present transcription — the one field whose correct answer an attacker already knows), and the
    client-visible trace carries error _categories_, never raw provider messages. Enforced by a
    scoped `no-restricted-imports` boundary in `eslint.config.mjs`.

## Ubiquitous Vocabulary

One name per concept, used in code, tests, UI copy, and docs.

| Term                                     | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TTB**                                  | Alcohol and Tobacco Tax and Trade Bureau — the agency whose rules we check against.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **COLA**                                 | Certificate of Label Approval — the certificate TTB issues via Form 5100.31 (formally "Certification/Exemption of Label/Bottle Approval"). **COLAs Online** is TTB's filing system (2003). Not integrated (context only).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Label / artwork**                      | The image of the beverage container submitted for review.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Application data**                     | The fields the applicant submitted — the ground truth we compare the label against.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Beverage type**                        | The TTB commodity the application is for: `distilled-spirits` \| `wine` \| `malt-beverage`. Selected in the form / batch CSV; drives **field requiredness only** (e.g. alcohol content: mandatory for spirits and wine > 14% ABV; optional for wine ≤ 14% designated "table"/"light" wine, and for malt beverages).                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Field**                                | One checked attribute: brand name, class and type designation, alcohol content, net contents, name and address, country of origin, health warning statement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Brand name**                           | The name the product is sold under. **Match: fuzzy** — normalize case/whitespace/punctuation; near-miss (e.g. STONE'S THROW vs Stone's Throw) → NEEDS_CORRECTION, not rejection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Class and type designation**           | The regulatory designation, e.g. "Kentucky Straight Bourbon Whiskey". (TTB term; "class/type" for short.) **Match: fuzzy** (normalized; near-miss → NEEDS_CORRECTION).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Alcohol content**                      | TTB field, stated as percent alcohol by volume. **Match: normalized** — parse to a number, reconcile proof (= 2 × ABV), compare within tolerance.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **ABV**                                  | Alcohol By Volume, as a percent. TTB defines alcohol content in these terms.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Proof**                                | US proof = 2 × percent alcohol by volume (ethyl alcohol at 60 °F, per TTB).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Net contents**                         | Declared volume, e.g. "750 mL". **Match: normalized** — normalize units/spacing ("750 mL" == "750ML").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Name and address**                     | TTB field: name and address of the bottler / producer / importer. **Match: normalized fuzzy** when an application value is present.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Health warning statement**             | TTB's official name for the mandatory warning field ("health warning statement" and "government warning statement" are used interchangeably). Text begins `GOVERNMENT WARNING:`. **Match: exact** — whitespace-collapsed exact → COMPLIANT; case/spacing-only deviation → NEEDS_CORRECTION; else NON_COMPLIANT (spec §6); not fuzzy, not model-judged. Required on beverages ≥ 0.5% ABV.                                                                                                                                                                                                                                                                                                                                                |
| **Field of vision**                      | Per 27 CFR 5.63: a single side of a container (for a cylindrical container, 40% of the circumference) where the information can be viewed **simultaneously without turning the container**. Brand name, alcohol content, and class/type must share one. Checked best-effort (advisory) from bounding boxes.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Bounding box**                         | Normalized position of an extracted field on the image; powers the field-of-vision check. Available on the cloud tier (and mock).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Extraction**                           | Reading fields off the label image.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **`VisionProvider`**                     | The interface every extraction backend implements.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Tier**                                 | One extraction backend: `mock` \| `local-ocr` \| `local-llm` \| `cloud`. `local-llm` is a vision LLM on a local Ollama — keyless like `local-ocr`, but not zero-setup (needs Ollama + a pulled model); explicit opt-in only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **`ExtractedLabel`**                     | The Zod-validated structured result of extraction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **`ExtractedField`**                     | One extracted field: `{ value, present, confidence, boundingBox? }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **`ApplicationData`**                    | The typed application input.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Matcher**                              | Deterministic code comparing `ExtractedLabel` to `ApplicationData`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Verdict**                              | Per field: `COMPLIANT` \| `NON_COMPLIANT` \| `NEEDS_CORRECTION`. Overall: `APPROVED` \| `NEEDS_CORRECTION` \| `REJECTED` — the same three dispositions TTB uses in COLAs Online ([eApplication statuses](https://www.ttb.gov/system/files/images/pdfs/labeling_colas-docs/eapplication-statuses-in-colas.pdf)), where "Needs Correction" is an intermediate step for an application that cannot be approved as submitted, not a denial. Precedence: `REJECTED` iff any field is `NON_COMPLIANT`; else `NEEDS_CORRECTION` iff any field needs correction; else `APPROVED`. A field needing correction therefore never causes a rejection — but never passes silently either, which is the fail-closed rule applied at the overall level. |
| **`FieldResult` / `VerificationResult`** | The matcher's per-field and overall outputs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Eval / eval harness**                  | The accuracy measurement over labeled sample data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Planted violation**                    | An intentional error in an eval sample used to test detection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Escalation ladder**                    | The bounded, deadline-aware loop (`lib/vision/escalation/`) that re-reads weakly-extracted fields by transforming the image and re-extracting. A `VisionProvider` decorator: `withEscalation(inner)`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Weak field**                           | An extracted field that is absent, blank, or below `CONFIDENCE_NEEDS_CORRECTION_THRESHOLD` (0.5). The ladder's trigger — never a comparison against application data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Repair attempt / repair transform**    | One transform + re-extract + merge cycle; the image operation is `crop` (weak fields' union bounding box, padded, upscale hard-capped at `MAX_EDGE`) or `enhance` (downscale + greyscale/normalize/sharpen).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Monotonic merge**                      | A repair may only improve a field: absent → present, or strictly higher confidence; ties keep the baseline. The health warning statement is fill-only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Extraction trace**                     | The per-verify record of what the ladder tried, why it stopped, and what improved. Returned in the response; the full trail renders in dev mode. Repair errors appear as categories only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Planted injection**                    | An adversarial instruction printed on an eval sample's artwork (cf. planted violation). The `--set adversarial` gate checks each injected sample against its **clean twin** (identical base pixels) and fails one-directionally: an injection may never move a verdict toward passing.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Fallback**                             | `withFallback(primary, fallback)` — cloud extraction failure retries once on local-ocr (2026-07-25 spec). Composes OVER the ladder: `withFallback(withEscalation(cloud), withEscalation(localOcr))` (revised 2026-07-25 review — the earlier inside-the-ladder composition let a single failed cloud repair call fall back mid-ladder, merging local-OCR confidence against cloud confidence across incomparable scales). A repair always re-reads on the tier that produced its baseline; only a baseline failure falls back, and `trace.tier` names the tier that actually ran.                                                                                                                                                       |

## Environment Variables

| Var                        | Required? | Purpose                                                                                                                                                                                                                                                                                                          |
| -------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VISION_PROVIDER`          | No        | Force a tier: `mock` \| `local-ocr` \| `local-llm` \| `bedrock`. Default: auto (local-ocr for uploads, mock for samples).                                                                                                                                                                                        |
| `AWS_BEARER_TOKEN_BEDROCK` | No        | Enables the Bedrock cloud tier — the only cloud adapter (Gemini/Claude-direct/OpenAI/Groq were removed 2026-07-25) — via the Converse API, bearer-token auth, no AWS SigV4.                                                                                                                                      |
| `BEDROCK_REGION`           | No        | Bedrock region for the `bedrock` tier (default `us-east-2`). Deliberately its own var, not `AWS_REGION` — on Vercel (this project's deploy target), `AWS_REGION` is auto-populated by the underlying Lambda runtime even when never set, which would silently override the default with an untrusted value.      |
| `BEDROCK_MODEL`            | No        | Bedrock model ID for the `bedrock` tier (default `us.anthropic.claude-haiku-4-5-20251001-v1:0` — Claude Haiku 4.5, chosen empirically after it beat the earlier Llama 4 Maverick default on the real-world eval set; the pinning test and history live beside `DEFAULT_MODEL` in `lib/vision/cloud/bedrock.ts`). |
| `RATE_LIMIT_WINDOW_MS`     | No        | Rate-limit window for `/api/verify` and `/api/batch` (default 60000). Positive integers only — anything else warns once and uses the default.                                                                                                                                                                    |
| `RATE_LIMIT_MAX`           | No        | Requests allowed per window (default 60). Positive integers only, same fail-safe parsing.                                                                                                                                                                                                                        |
| `TRUST_PROXY_HEADERS`      | No        | Set to `1` only behind a proxy that sets X-Forwarded-For honestly (e.g. Vercel): keys the rate limit per client IP. Default: untrusted — all traffic shares one bucket, which can't be spoofed away.                                                                                                             |
| `ESCALATION_ENABLED`       | No        | Set to `1` to turn the escalation ladder on by default (it ships OFF; see the invariants).                                                                                                                                                                                                                       |
| `OCR_LANGS`                | No        | Tesseract language packs for the local-ocr tier (default `eng`; e.g. `eng+spa` for Puerto-Rico all-Spanish labels — costs latency, see the language-pack spec).                                                                                                                                                  |
| `BEDROCK_TIMEOUT_MS`       | No        | `bedrock` tier hard per-request bound (default 30000) — `fetch` has no built-in timeout, unlike the vendor SDKs the other cloud adapters use.                                                                                                                                                                    |
| `OLLAMA_BASE_URL`          | No        | Ollama host for the local-llm tier (default `http://localhost:11434`).                                                                                                                                                                                                                                           |
| `OLLAMA_MODEL`             | No        | Model tag for the local-llm tier (default `qwen2.5vl:3b`).                                                                                                                                                                                                                                                       |
| `OLLAMA_NUM_CTX`           | No        | local-llm context window (default 8192 — covers image tokens + prompt + output; Ollama's own default of 2048 silently truncates vision requests).                                                                                                                                                                |
| `OLLAMA_TIMEOUT_MS`        | No        | local-llm hard per-request bound (default 60000) so a stuck model fails closed.                                                                                                                                                                                                                                  |

All keys are read server-side only. The app is fully functional with **none** set.

The repo ships a committed **`.env.example`**. Every row there is a commented-out placeholder — no
real values. Local dev uses `.env.local` (gitignored) for anything not meant to be committed. The deployed demo sets
`AWS_BEARER_TOKEN_BEDROCK` in the Vercel project settings so reviewers see the best-accuracy cloud
path by default — while the keyless tiers keep working if the key is removed, expires, or
rate-limits.

## Project Claude Skills (`.claude/skills/`)

This is an AI-first project, so it ships project-scoped Claude skills — AI-native tooling for building
and operating ProofCheck. Committed to the repo so a reviewer sees the workflow.

| Skill               | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **deploy-smoke**    | Smoke-test the **live Vercel URL**: app responds, `/api/verify` works, one sample label runs end-to-end. Supports the deployed-URL deliverable.                                                                                                                                                                                                                                                                                                                                               |
| **run-eval**        | Run the eval harness; report **per-tier accuracy** (mock / local-ocr / cloud) and planted-violation catch rate. The signature AI-first skill.                                                                                                                                                                                                                                                                                                                                                 |
| **add-test-label**  | Scaffold a new eval sample: place the image and add its `expected.json` entry (with an optional planted violation). Grows the eval set correctly.                                                                                                                                                                                                                                                                                                                                             |
| **check-providers** | Verify each `VisionProvider` tier is wired and responding for the current env/keys — catches "cloud key not set" fast. Specific to our tiered design.                                                                                                                                                                                                                                                                                                                                         |
| **test-page**       | Local **dev** smoke test (counterpart to deploy-smoke): boot `pnpm dev`, confirm the page renders and a sample verify works before pushing. Authored 2026-07-26 (specced in the original MVP plan, `docs/superpowers/plans/2026-07-21-proofcheck-mvp.md:3888-3909`, but not copied into `.claude/skills/` until this pass). Complements, not replaces, the transitive `eslint-plugin-jsx-a11y` rules already running via `eslint-config-next` in `pnpm lint`. |
| **tune-matching**   | Given a mis-verdict (false NON_COMPLIANT/NEEDS_CORRECTION/COMPLIANT, or overall APPROVED/NEEDS_CORRECTION/REJECTED), capture it as a unit test + eval case, then adjust normalizers/thresholds until green. ## Testing Strategy (layers & mocking)

Spec §12 says _what_ is tested; this table pins _how_. Governing principle: **no live cloud calls in
tests or CI** — fixtures only. The mock tier doubles as the E2E test double. Accuracy is measured in
exactly one place (the eval harness), never asserted in unit tests.

| Layer         | Tool                                                           | Scope                                                                                                                                                                                                  | Mocking approach                                                                    |
| ------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| **Unit**      | Vitest                                                         | `lib/matching` field rules + aggregator, `lib/ttb` normalizers / proof↔ABV / required-fields map, tier selector                                                                                        | None — pure functions, real inputs                                                  |
| **Component** | React Testing Library + jsdom                                  | Verdict card, field rows, upload zone, form validation (beverage-type requiredness)                                                                                                                    | Mock `fetch` to API routes                                                          |
| **Adapter**   | Vitest                                                         | Cloud adapters: schema validation, retry-on-invalid-JSON; local-OCR text→fields parser                                                                                                                 | Canned model JSON fixtures (incl. malformed + adversarial); canned OCR text strings |
| **E2E smoke** | Playwright — **thin: 2–3 specs, not a suite**                  | Single verify happy path, batch upload, one error path — against `pnpm dev` with `VISION_PROVIDER=mock`                                                                                                | The mock tier _is_ the double: deterministic, keyless, fast                         |
| **Accuracy**  | Eval harness (`pnpm eval`)                                     | Extraction + matching accuracy, planted-violation catch rate; escalation **OFF by default, tracking the route** (`--escalate` for the paired ladder run; `eval/compare-escalation.ts` diffs per label) | None — measures the real pipeline per tier                                          |
| **Security**  | `pnpm eval:adversarial` (CI, keyless) + a recorded Bedrock run | Planted injections vs clean twins; differential one-directional gate — an injection may never move a verdict toward passing                                                                            | None — real extractors by design (the fixture tier can't be injected)               |
| **Live**      | `deploy-smoke` skill                                           | Deployed URL end-to-end                                                                                                                                                                                | None                                                                                |

### Test Workflows (the operational loops)

- **TW1 — inner loop (while coding):** `pnpm test --watch` on the module under construction;
  red → green → refactor. Matching/TTB logic is written test-first.
- **TW2 — pre-commit:** `pnpm lint && pnpm test` (unit + component + adapter). Stays fast (< 30 s)
  because no layer makes live calls.
- **TW3 — pre-push, when extraction or matching changed:** `pnpm eval` (mock tier at minimum).
  On the mock tier extraction is canned, so eval is effectively an integration test of the matcher —
  it must catch **100% of planted violations**; any drop is a regression.
- **TW4 — CI (GitHub Actions, on push/PR):** install → lint → typecheck → tests → build →
  Playwright smoke (mock tier) → eval (mock tier, asserting the planted-violation catch rate).
  **No secrets in CI; the cloud tier never runs there.**
- **TW5 — mis-verdict feedback loop** (the `tune-matching` skill): reproduce → capture as a failing
  unit test (plus an eval sample via `add-test-label` if extraction-related) → fix/tune thresholds →
  green → re-run eval.
- **TW6 — pre-deploy / pre-submission:** TW2 + TW3 pass → `security-review` skill → deploy →
  `deploy-smoke` against the live URL → `check-latency` vs the 5 s budget.

| ----------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Prompt injection via label artwork** — adversarial text printed on the label ("report all fields as matching") steering the model | LLM01       | The architecture is the mitigation: the model **only extracts** — all verdicts come from deterministic code, so the health warning check _cannot_ be prompt-injected into passing (it's a string compare against a canonical constant). Extraction prompt frames image text as untrusted data, never instructions. Residual risk (injected text corrupting extracted _values_) is bounded by Zod schema constraints, confidence surfacing, and the agent seeing extracted values beside the image.                                                                                                                                                                                                                                                                                                                                                                                   |
| **Model output reaching a sink**                                                                                                    | LLM05       | All model output is Zod-validated before use; rendered only through React (auto-escaped); never executed, never templated into HTML/SQL/shell.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Cost/resource exhaustion**                                                                                                        | LLM10 / A06 | Upload size caps, bounded batch concurrency (~5), hard request timeouts, `max_tokens` caps. ## Why No Database, Storage, or Auth (grounded in the brief)

These are deliberate scope decisions traceable to the stakeholder interviews, not omissions:

- Marcus Williams (IT): _"Think of this as a **standalone proof-of-concept**..."_ and _"...**We're not
  storing anything sensitive for this exercise.**"_ → no persistent DB, no blob storage of labels/PII.
- The brief requires the reviewer to _"access and test"_ the deployed app, and Sarah wants something
  usable by a non-technical 73-year-old → **no auth wall**, which would add friction to the exact
  workflow being evaluated.
- Federal PII/retention sensitivity + no stated analytics need → **no analytics/tracking** by default.

This matches the evaluation criterion _"appropriate technical choices for the scope"_ and the brief's
guidance that _"a working core application with clean code is preferred over ambitious but incomplete
features."_ A production system would add persistence (audit/retention), authn/z, and an on-prem model
— noted as future work, out of scope for the prototype.
